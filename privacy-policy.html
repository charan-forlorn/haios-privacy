Privacy Policy

HAIOS — Dropbox Read-Only Connector · Version R1 · Effective date: 18 November 2026

Scope notice. This policy describes the current R1 Dropbox connector: a local Windows/Python command-line component for account and storage summaries. It is not a hosted Dropbox file browser, sync service, backup service, or document-indexing service. The connector is not currently activated in the production Hermes/MCP runtime.

1. Who operates HAIOS

HAIOS is a software project maintained by the individual developer associated with the GitHub account charan-forlorn (“the Developer”, “we”, or “us”). This notice applies to the HAIOS R1 Dropbox read-only connector and this policy website. HAIOS is not represented by this notice as a corporation or other registered legal entity.

2. What the connector does

When a user chooses to run the connector, it uses a Dropbox OAuth access token supplied by the user after authorization with Dropbox. The connector validates that the grant is a Bearer token with exactly the account_info.read scope and a valid lifetime. It makes only these Dropbox API v2 calls:

  • users/get_current_account — obtains the account display name, email address, email-verification flag, and account type.
  • users/get_space_usage — obtains storage usage and allocation information.

The connector does not request or access Dropbox file or folder listings, file names, file paths, file metadata, file contents, shared links, revisions, or team content. It has no Dropbox upload, download, edit, move, share, or delete operation.

3. Information processed

  • OAuth grant information: the access token, scope, token type, expiry duration, issue timestamp, and a boolean indicating whether a refresh token was supplied. The access token is received through standard input, held in process memory, and sent to Dropbox in the HTTPS Authorization header for the two approved API calls. The connector does not support or store refresh tokens.
  • Account information: Dropbox returns the account display name, email address, email-verification status, and account type. The full email address is handled transiently in process memory so it can be masked. The connector's output contains only the masked email address (for example, j***@example.com), not the full email address.
  • Storage information: storage allocation type, bytes used, allocated bytes when provided by Dropbox, and derived remaining bytes and usage percentage when calculable.
  • Snapshot metadata: the time at which the local connector creates the normalized snapshot.

The connector does not collect the user's Dropbox password. Dropbox authentication takes place through Dropbox's own authorization experience; the connector receives an access token, not the user's password.

4. Why information is processed

The information is processed only to authenticate the limited API request, validate the requested permission and token lifetime, show the user a current account/storage summary, and report whether the request succeeded. The R1 connector does not use Dropbox information for advertising, behavioural profiling, sale of data, or training AI models. It does not send Dropbox API response data to a separate AI model provider.

5. Where information goes and who receives it

  • Dropbox: the connector sends the access token and the two API requests directly to Dropbox over HTTPS. Dropbox processes the request and returns the requested account and storage information under Dropbox's own terms and privacy practices. See the Dropbox Privacy Policy.
  • GitHub Pages: this public policy website is hosted by GitHub Pages. GitHub states that it logs and stores visitors' IP addresses for security purposes. See the GitHub Privacy Statement.

The R1 connector does not upload the Dropbox summary to a HAIOS-operated cloud database, object store, analytics service, advertising network, or third-party AI service. No sale of Dropbox user data takes place. The Developer does not receive the user's Dropbox password or retain the access token.

6. Storage and retention

The connector is designed to process the token and API responses in local process memory. It does not create a credential file, database, cache, or server-side account record. It emits a normalized, redacted JSON summary to standard output and does not itself write that summary to persistent storage.

The person operating the local computer may choose to redirect or save command output, or their terminal, shell, operating system, backup, or logging configuration may retain it. Any such operator-controlled copy is outside the connector's own storage mechanism and should be protected and deleted by that operator according to their needs. Python and the operating system do not guarantee forensic zeroization of all in-memory copies when a process exits.

7. Security measures

The R1 implementation uses HTTPS with standard TLS certificate validation, rejects HTTP redirects, restricts requests to the two fixed endpoints, checks the exact required scope, enforces token-expiry metadata and request-size/time limits, masks email addresses, and sanitizes error output. These measures reduce risk but cannot guarantee absolute security. Users should protect their devices and never share access tokens or application secrets.

8. User choices and access revocation

Use of the connector is optional. A user can stop running it and can manage or revoke the application's authorization through their Dropbox account's connected-app controls. Revoking authorization prevents future API access using that authorization, subject to Dropbox's token and revocation behavior. Because the R1 connector does not maintain a server-side account or token store, it has no HAIOS-hosted account record to delete.

9. International processing

The connector runs locally on the operator's Windows computer. Dropbox processes API requests through Dropbox's infrastructure, and GitHub hosts this policy website. Those providers may process service and security data in locations determined by their own services and terms. The Developer does not operate a separate cloud repository for R1 Dropbox account or storage data.

10. Changes to this policy

This notice will be updated if the connector's data use, scopes, endpoints, storage, sharing, or deployment model materially changes. Features such as file metadata access, file-content retrieval, synchronization, indexing, or cloud AI processing are outside R1 and are not authorized by this policy. They require a separate design, appropriate authorization, and an updated privacy notice before use.

11. Contact and privacy questions

For questions about this policy or to request a private contact route for a privacy matter, use the Developer's GitHub profile. Do not post access tokens, passwords, full Dropbox account details, or other sensitive personal information in public repository issues.

This notice describes the implemented R1 connector boundary. It is informational and is not a legal opinion or a representation that every future HAIOS component has the same data practices.

นโยบายความเป็นส่วนตัว (ภาษาไทย)

ขอบเขต: นโยบายนี้ครอบคลุม Dropbox Connector รุ่น R1 ของ HAIOS ซึ่งเป็นโปรแกรม Command Line ที่ทำงานภายในเครื่อง Windows/Python เพื่ออ่านข้อมูลบัญชีและสถิติพื้นที่จัดเก็บเท่านั้น ปัจจุบัน Connector ยังไม่ได้เปิดใช้งานใน Hermes/MCP Runtime สำหรับ Production

1. ผู้ดูแล HAIOS

HAIOS เป็นโครงการซอฟต์แวร์ที่ดูแลโดยนักพัฒนารายบุคคลผ่านบัญชี GitHub charan-forlorn นโยบายนี้ไม่ใช่การแสดงว่า HAIOS เป็นบริษัทหรือนิติบุคคลที่จดทะเบียนแล้ว

2. ข้อมูลที่ Dropbox Connector เข้าถึง

Connector ใช้ Dropbox OAuth Access Token ที่ผู้ใช้ได้รับจากการอนุญาตกับ Dropbox โดยตรวจสอบสิทธิ์ account_info.read เท่านั้น และเรียก API เพียง 2 รายการ ได้แก่ users/get_current_account สำหรับข้อมูลบัญชี และ users/get_space_usage สำหรับข้อมูลพื้นที่จัดเก็บ

Connector ไม่อ่านรายชื่อไฟล์ โฟลเดอร์ ชื่อหรือเส้นทางไฟล์ Metadata หรือเนื้อหาไฟล์ ไม่ค้นหา ดาวน์โหลด อัปโหลด แชร์ แก้ไข ย้าย หรือลบไฟล์ Dropbox

3. ประเภทข้อมูลที่ประมวลผล

  • OAuth Access Token, Scope, Token Type, อายุ Token, เวลาออก Token และสถานะว่ามี Refresh Token หรือไม่ โดย Token รับผ่าน Standard Input และอยู่ในหน่วยความจำระหว่างทำงานเท่านั้น
  • ชื่อบัญชี อีเมล สถานะยืนยันอีเมล และประเภทบัญชีจาก Dropbox โดยอีเมลเต็มถูกประมวลผลชั่วคราวเพื่อปกปิด และผลลัพธ์แสดงเฉพาะอีเมลที่ปกปิดแล้ว
  • ประเภทโควตาพื้นที่จัดเก็บ จำนวนไบต์ที่ใช้ จำนวนไบต์ที่จัดสรร (เมื่อ Dropbox ส่งข้อมูลนี้มา) และค่าคงเหลือ/เปอร์เซ็นต์การใช้งานที่คำนวณได้
  • เวลาที่สร้าง Snapshot ในเครื่อง

Connector ไม่รับหรือจัดเก็บรหัสผ่าน Dropbox การเข้าสู่ระบบและการอนุญาตเกิดขึ้นผ่านระบบของ Dropbox เอง

4. วัตถุประสงค์

ใช้ข้อมูลเพื่อยืนยันสิทธิ์ ตรวจสอบขอบเขต OAuth เรียกข้อมูลบัญชีและพื้นที่จัดเก็บ และแสดงผลสรุปแก่ผู้ใช้งานเท่านั้น R1 ไม่ใช้ข้อมูลเพื่อโฆษณา การติดตามพฤติกรรม การขายข้อมูล หรือฝึกโมเดล AI และไม่ส่งข้อมูลตอบกลับจาก Dropbox ไปยังผู้ให้บริการโมเดล AI รายอื่น

5. การส่งต่อข้อมูล

Connector ส่ง Access Token และคำขอ API ทั้งสองรายการไปยัง Dropbox โดยตรงผ่าน HTTPS เพื่อให้ Dropbox ประมวลผลตามนโยบายของ Dropbox ส่วนเว็บไซต์นโยบายนี้โฮสต์บน GitHub Pages ซึ่ง GitHub ระบุว่าบันทึกและจัดเก็บ IP Address ของผู้เข้าชมเพื่อความปลอดภัย HAIOS R1 ไม่อัปโหลดข้อมูลสรุปไปยังฐานข้อมูล Cloud, Object Storage, Analytics, เครือข่ายโฆษณา หรือบริการ AI ภายนอก และไม่มีการขายข้อมูล

6. การจัดเก็บและระยะเวลาเก็บรักษา

Connector ประมวลผล Token และ API Response ในหน่วยความจำของโปรเซสภายในเครื่อง ไม่สร้างไฟล์เก็บ Credential, Database, Cache หรือบัญชีผู้ใช้บนเซิร์ฟเวอร์ ผลลัพธ์ JSON ที่ถูกปกปิดจะถูกส่งออกทาง Standard Output เท่านั้น ตัวโปรแกรมไม่ได้บันทึกผลลัพธ์นั้นลง Persistent Storage โดยตรง อย่างไรก็ตาม ผู้ดูแลเครื่องอาจเลือกบันทึก Output หรือมีระบบ Terminal/Logging/Backup เก็บไว้เอง ซึ่งเป็นความรับผิดชอบของการตั้งค่าเครื่องนั้น Python และระบบปฏิบัติการไม่รับประกันการล้างข้อมูลจากหน่วยความจำอย่างสมบูรณ์ในเชิง Forensic เมื่อโปรเซสจบลง

7. มาตรการความปลอดภัย

ใช้ HTTPS/TLS ตรวจสอบใบรับรอง ปฏิเสธ Redirect จำกัด API ให้เหลือสอง Endpoint ตรวจสอบ Scope และอายุ Token จำกัดขนาดข้อมูลและเวลารอ ปกปิดอีเมล และลดรายละเอียด Error ที่อาจเปิดเผยข้อมูล มาตรการเหล่านี้ช่วยลดความเสี่ยงแต่ไม่สามารถรับประกันความปลอดภัยได้ทั้งหมด ผู้ใช้ควรปกป้องอุปกรณ์และไม่เปิดเผย Token หรือ App Secret

8. สิทธิ์และการยกเลิกการเชื่อมต่อ

การใช้งาน Connector เป็นทางเลือก ผู้ใช้สามารถหยุดใช้งานและจัดการหรือเพิกถอนสิทธิ์แอปผ่านการตั้งค่า Connected Apps ของบัญชี Dropbox ได้ เนื่องจาก R1 ไม่มีระบบเก็บบัญชีหรือ Token บนเซิร์ฟเวอร์ HAIOS จึงไม่มีระเบียนบัญชีบน HAIOS ให้ลบ

9. การประมวลผลในต่างประเทศและการเปลี่ยนแปลง

Connector ทำงานในเครื่อง Windows ของผู้ใช้ ส่วน Dropbox และ GitHub ประมวลผลข้อมูลที่จำเป็นต่อบริการตามโครงสร้างพื้นฐานและเงื่อนไขของผู้ให้บริการนั้น การเพิ่มสิทธิ์อ่าน Metadata/เนื้อหาไฟล์ การ Sync การทำ Index หรือ Cloud AI Processing อยู่นอกขอบเขต R1 และต้องผ่านการออกแบบ การอนุญาต และปรับปรุงนโยบายก่อน

10. ติดต่อ

สอบถามเกี่ยวกับนโยบายนี้หรือขอช่องทางติดต่อส่วนตัวได้ผ่าน GitHub Profile ของผู้พัฒนา โปรดอย่าโพสต์ Token รหัสผ่าน ข้อมูลบัญชี Dropbox แบบเต็ม หรือข้อมูลส่วนบุคคลที่ละเอียดอ่อนใน GitHub Issue สาธารณะ
